# 自定义写入令牌设计

## 目标

允许用户在新建集合时选择随机令牌或自定义令牌，并在后续“令牌管理 → 轮换”中修改令牌规则、生成或输入新令牌。现有集合和现有令牌保持兼容。

## 令牌规则

令牌字符白名单为 `A-Z a-z 0-9 _ - @`，最大长度保持 128 位。默认规则为：最小长度 8 位，必须包含大写字母、小写字母和数字；`@` 可使用但不强制。随机模式继续使用现有高熵生成器，并生成符合当前规则的令牌。

用户可配置：最小长度（8–128）、是否要求大写字母、是否要求小写字母、是否要求数字、是否允许 `@`。最小长度不能大于最大长度；至少保留一种字符类别。规则配置保存到集合设置中，但服务端只保存令牌哈希，不保存令牌明文。

## 创建流程

新建集合的令牌步骤提供“随机生成”和“自定义令牌”两种模式。随机模式为默认模式；自定义模式显示规则配置和令牌输入框，并实时提示长度、字符集和各项要求。提交时前端即时校验，服务端再次校验令牌及规则后再创建集合。

## 轮换流程

令牌管理中的轮换流程允许选择规则、生成符合规则的随机令牌或输入自定义令牌。轮换请求携带当前令牌、新令牌及新规则；服务端先验证当前令牌，再验证新令牌和规则，成功后原子更新令牌哈希与规则。旧令牌立即失效，用户必须重新绑定其他设备和 bookmarklet。

规则只影响后续新建或轮换，不会重新评估已有令牌，也不会因升级而使已有集合失效。恢复文件、粘贴令牌和普通写入请求均使用集合当前的令牌格式校验。

## 安全与兼容性

- 随机令牌仍为推荐选项；自定义令牌即使满足格式，也可能因用户选择而熵较低。
- 服务端继续使用 SHA-256 哈希存储，并在所有写入入口执行格式校验和限流。
- 拒绝空白、控制字符、未列入白名单的特殊字符、明显重复模式和常见弱令牌。
- `@` 通过现有 URL 编码和 bookmarklet 参数编码传输，不允许空格、引号、反引号、斜杠、问号等易混淆字符。
- 旧版集合没有规则配置时使用兼容默认规则；现有 16 位以上令牌继续可用。
- 新规则写入失败时不改变旧令牌或旧规则；轮换成功后再更新本地令牌和备份状态。

## 验证

覆盖：默认随机创建、自定义令牌创建、`@` 字符、长度和字符类别校验、前后端规则一致、轮换后旧令牌失效、已有令牌兼容、弱令牌拒绝、规则持久化和错误回滚。
