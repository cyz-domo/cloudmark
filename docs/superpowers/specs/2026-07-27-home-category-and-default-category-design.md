# 首页展示组别与默认分类设计

## 目标

为每个集合增加一个由所有访问者共享的首页展示组别，并将集合设置中的默认分类改为分类选择器，同时保留输入新分类的能力。

## 用户行为

- 集合设置新增“首页展示组别”，可选择“全部分组”、已有父组或子组。
- 保存后当前页面立即切换到首页展示组别；之后打开该集合首页的访问者默认进入该组。
- 默认分类改为下拉选择已有分类，并提供“新建分类/自定义输入”入口；输入的新分类沿用现有长度和非空校验。
- 重命名父组或子组时，同步更新 `home_category`、`default_category`、分类顺序和当前页面状态中的路径。
- 删除首页展示组别或其父组时，`home_category` 回退为全部分组；删除默认分类或其父组时，`default_category` 回退为 `default`。
- 未设置首页展示组别时保持全部分组的现有行为。

## 实现方案

- 在 `collections` 表新增 `home_category` 字段，使用迁移 `0006_home_category.sql`，默认值为空字符串。
- 扩展 `CollectionSettings`、D1 行转换、创建/更新集合设置 API 和校验 schema。
- 设置字段组件接收当前分类列表；默认分类使用已有 Select，选择“新建分类”时显示文本输入；首页展示组别只使用 Select。
- 集合页从服务端设置读取 `homeCategory`，首次应用页面数据时设置当前筛选分类；保存设置后通过现有 `onSaved` 回调立即更新筛选。
- 重命名和删除服务端操作在同一数据库更新中维护两个分类设置，保证刷新后与前端一致。

## 验证

- 应用本地 D1 迁移并确认集合查询包含新字段。
- 运行 TypeScript 类型检查与 `git diff --check`。
- 本地验证：选择首页展示组别后刷新/重新打开仍进入该组；重命名父组会同步子组和两个设置；删除相关组别会按规则回退。
